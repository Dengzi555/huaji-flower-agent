# 内联详情与错字确认

## 详情栏占据真实布局空间

右侧详情改为 `main` 内的第二个网格列，主内容使用 `minmax(0,1fr)`。展开时主内容缩窄、关闭时恢复，账本横向滚动仍限制在表格容器内。宽度不超过 1000px 时改成上下排列，不用覆盖内容的浮层。

`setInspector` 同步维护 `inspector-open` 类和按钮的展开状态，页面布局与实际开关保持一致。

## 没有大模型也能处理一部分错字

已有的词表负责“红玫”“乌梅包括”等登记过的简称或短语。“红梅”不能直接加入静默替换词表：它有可能真指梅花，目录扩展后更不能一律改成玫瑰。

本次增加有限候选策略：目录没有“红梅”时，根据“红玫瑰”检索候选，仍约束朵数、品种、类型及原有条件；无论候选是否唯一，必须先请用户确认。选择候选并重新提交后才进入查询。原问题保留，任务卡记录 `suggested_correction`，澄清后的调查通过父任务关联。

- `99红梅`：推荐 99 朵红玫瑰，确认前不查询。
- `红梅`：没有规格，展示符合条件的多个候选，不猜选其中一款。
- `66红梅`：目录没有该规格时保持澄清，不放宽为其他朵数。
- 目录确实存在红梅时：按目录正常匹配，不触发本规则。

这不是通用拼写纠错。目前只覆盖这项登记策略；其他错字仍可能无法识别。未来可增加经过评测的同音、相似字检索或模型候选建议，但这些只提出候选，不能绕开目录和确认直接执行。

125 项测试通过，包括两项新增错字回归。Edge 验证主内容右边界与详情栏左边界相等，没有重叠。“99红梅2026-10-25销量下降原因”先返回需要补充信息、0 类数据已查询；点击推荐商品并重新提交后调查完成、4 类数据已查询。
