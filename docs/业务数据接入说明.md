# 业务数据接入说明

## 先确定调查对象

第一版调查一个 SKU 在目标自然日相对前一日的变化。

所有来源必须对齐：同一店铺/渠道范围、SKU ID、Asia/Shanghai 自然日、币种、支付状态、退款处理方式、访客和买家去重规则。当前键是 `table + sku_id + date`，不支持多个店铺相同 SKU ID 混用；多店铺必须先选定一个范围，或先进行明确的归一化。

最小样例只需两个日切片。业务验证建议另准备更长历史和小时级数据，用于对照星期、活动和缺货时间重合；这些还不在第一版分析范围内。

## 统一包头

```json
{
  "schema_version": 1,
  "sample_data": true,
  "timezone": "Asia/Shanghai",
  "currency": "CNY",
  "sales": [],
  "traffic": [],
  "inventory": [],
  "promotions": []
}
```

`sample_data` 必填，合成数据用 true。用户业务数据用 false 仅表示来源标签，不是程序已经证实真实性。

## 每条记录公共字段

| 字段 | 示例 | 说明 |
|---|---|---|
| `sku_id` | `SHOP1-SKU100` | 跨来源一致的 SKU 标识，不是商品标题 |
| `date` | `2026-10-23` | 数据覆盖的自然日 |
| `source_id` | `erp-export-v1` | 实际来源/导出批次标识 |
| `observed_at` | `2026-10-24T08:00:00+08:00` | 数据更新时间，必须带时区 |
| `status` | `ok` | `ok / unavailable / delayed` |
| `reason` | `Export not ready` | 非 ok 时的可选说明 |

程序另记录 `retrieved_at`，表示工具何时读取这条数据，与业务数据更新时间分开。

## 四类指标

### sales

```json
{
  "sku_id": "SHOP1-SKU100",
  "date": "2026-10-23",
  "source_id": "sales-export",
  "observed_at": "2026-10-24T08:00:00+08:00",
  "status": "ok",
  "paid_orders": 60,
  "paid_buyers": 50,
  "units_sold": 80,
  "paid_revenue": 4000
}
```

支付订单数不是支付买家数，同一买家可能下多单；支付件数也不等于订单数。V1 使用支付口径，不混入待付款、退款负数或净销售额。若业务需要净口径，应扩展 Schema 并重写相关断言。

### traffic

公共字段外提供 `visitors`：商品访客去重 UV。

支付转化率 = 同口径去重支付买家数 / 商品访客 UV。程序不会用销量除访客数代替转化率。分母为零时不计算比率。

如果平台的买家和访客归因窗口不同，二者不能直接相除。V1 假定同日同范围的买家属于对应访客集合；买家大于访客会标为数据冲突，而不是计算超过 100% 的转化率。

### inventory

公共字段外提供：

```json
{"out_of_stock_minutes": 180, "monitored_minutes": 1440}
```

“缺货”应按同一库存策略定义，例如可售库存为零；不要混用实物库存、锁定库存和可售库存。

监测不足全天时，程序标记观察缺口，不用局部窗口推断全天状态。整日无货却有当日支付，会标记需要核对的数据冲突；预售、补单、归因滞后等业务也可能解释这种现象，所以不能自动断言库存系统错误。

### promotions

公共字段外提供 `active` 布尔值及 `campaign_name` 字符串。第一版只比较活动是否开启，不解析券、满减、会员价、组合装或平台补贴。

若当天存在部分时段活动，这个日级布尔值不足以精确调查，应后续扩展开始/结束时间。不能据此判断促销增量或价格弹性。

## 缺失怎么处理

无法提供的数据应使用 unavailable/delayed，或不提供该日期记录；工具会明确返回缺口。不要用 0 填充未知访客、销量或缺货时长。

第一版不需要个人信息；请不要把姓名、手机号、收货地址、用户 ID、登录 Cookie、平台 Token 放进数据文件。

## 有哪些可用来源

销售和商品访客通常可来自你有权使用的商家后台导出；库存可来自 ERP/WMS 或库存监控记录；促销来自活动配置导出。不同系统提供字段不同，需要先检查实际导出，不假定特定平台接口已经接通。

第一版没有直接读取 Excel/CSV 的导入器。推荐先按 `data/sample.json` 转成标准化 JSON，后续再将这一步独立做成 Adapter，并保留映射规则和验证日志。
