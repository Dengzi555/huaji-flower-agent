# 商品识别与目录维护

花迹将商品维护与经营调查放在同一工作台。商品名称和标签可以修改，历史经营快照与任务证据仍按原版本保留。

## 图片识别

上传 JPG、PNG 或 WebP 商品图，选择门店及可选节日。视觉模型返回七个字段：四字前缀、规格、主花材、搭配花材、商品类型、用途关键词、送礼对象。

- 花材、数量、形态属于图片事实，遮挡或无法确认时留空，不自动套用示例中的数量和品种。
- 四字前缀、用途词及送礼引导属于营销建议，可由员工编辑，不冒充图片识别结果。
- 标题由程序按门店规则组合；门店风格、配送尾缀与节日规则来自 `data/product_naming.json`。
- 图片识别结果不会自动变成售卖商品或经营事实。上传上限 10 MB，图片不作为公开仓库资料保存。

## 目录巡检与修正

巡检检查标题格式、配送尾缀、用途及送礼词、结构化字段和业务标签。模型修正必须保留原记录的花材、类型与明确数量；资料不足时转人工补充。

提交修正时校验目录指纹和版本，SQLite 事务保存修改结果与历史。两个旧版本请求不能相互覆盖；重启后恢复已保存的目录修订。新导入的数据版本不套用旧目录的修订。

## 配置

在系统设置中单独配置视觉模型，或在项目根目录 `.env` 填写：

```dotenv
VISION_BASE_URL=https://your-provider.example/v1
VISION_MODEL=your-vision-model
VISION_API_KEY=your-key
VISION_TIMEOUT_SECONDS=45
```

示例均为占位符。密钥只保存在本地，不通过配置读取接口回显。文本与视觉配置更新共用锁并保留其他变量。

## 验证

```bash
python -X utf8 -m unittest tests.test_product_identification tests.test_product_maintenance tests.test_api_settings -v
```

测试使用合成商品、模拟模型响应和临时数据库，覆盖缺字段、错误事实、并发版本冲突、保存恢复和配置隔离，不代表真实图片识别准确率。
