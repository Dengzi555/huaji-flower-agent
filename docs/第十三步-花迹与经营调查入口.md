# 花迹与经营调查入口

助手叫“花迹”，门店品牌仍然叫“花仙女”。品牌标志沿用现有花瓣元素，助手名称统一到页面标题、导航品牌位和调查回复署名。

欢迎语改为“循着花迹，看清每一次经营变化。”入口只承担提问与明确范围，不提前展示调查结论。

## 为什么移除十个快捷案例

“流量下降”“活动结束”是需要查证的候选信号，不适合成为提问前必须选择的答案。旧按钮还绑定固定 SKU 和数据最后一天，适合演示，不能代替日常经营操作。

现在直接输入问题；本次查询事项、商品规格和日期默认展开。商品选项仍从当前门店的 `/api/meta` 获取，明确选择后随请求传给后端。输入区移到欢迎文案下，避免首屏文案与页面底部输入框相隔太远。没有增加默认日期，不把数据最后一天当成“昨天”。

自然语言与显式选项都走原有任务解析、路由和工具链。存在歧义时仍澄清，缺失记录仍报缺数据，前端不会编造指标。数据来源、规则执行及尚未接入模型的信息放在“数据与能力说明”。

## 学习时可以看哪里

- `web_assets/index.html`：文案、输入范围和结果区域的结构。
- `web_assets/app.js` 的 `loadMeta`：商品目录来自接口；已移除硬编码的十条案例。
- `web_assets/app.js` 的表单提交：问题、可选 SKU、日期和意图一并交给后端。
- `web_assets/operations.css`：调查区明暗主题；解决输入框外白色渐变与蓝色发送按钮。

同时修复“新建调查”在其他模块下只重置任务、不切换页面的问题，现在点击后进入调查并聚焦输入框。

## 本次验证

JavaScript 语法检查通过。Edge 实际输入“99红玫2026-10-25为什么卖少了？”：识别为 99 朵红玫瑰花束，调查完成，返回销量、访客和转化率，并给出带来源的候选信号。输入“99红玫销量下降原因”：返回需要补充日期，没有猜测日期或执行调查。

后端业务逻辑未更改；仍然是规则工作流，尚未接入大模型。
