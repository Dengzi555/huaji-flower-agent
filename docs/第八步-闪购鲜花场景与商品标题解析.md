# 第八步：闪购鲜花场景与商品标题解析

## 先理解商品身份与营销标题

以 `【炽热爱意】99朵红玫瑰花束送女友送爱人生日礼物生日鲜花花店鲜花上门情人节鲜花` 为例：

| 字段 | 内容 | 用途 |
|---|---|---|
| SKU | FLR-ROSE-99-BOUQUET | 连接销售、流量、库存、活动四类数据 |
| short_name | 炽热爱意 | 简短花名，方便自然语言提问 |
| stem_count | 99 | 一件成品的朵数，不是卖出 99 件 |
| variety | 红玫瑰 | 花材品种/颜色 |
| product_type | 花束 | 区分花束与抱抱桶 |
| name | 完整长标题 | 商品展示、完整标题粘贴查询 |
| occasion_keywords | 生日礼物、生日鲜花、情人节鲜花等 | 营销标签，不唯一识别商品，不证明实际促销 |

目录中目前有五款商品：

| 花名 | 规格 | 演示问题 |
|---|---|---|
| 炽热爱意 | 99朵红玫瑰花束 | 缺货时长增加 |
| 怦然心动 | 19朵红玫瑰花束 | 流量和销量同降，可追加渠道分析 |
| 温柔时光 | 19朵粉康乃馨花束 | 模拟满减券结束 |
| 心动满怀 | 33朵红玫瑰抱抱桶 | 库存缺失、流量延迟 |
| 向阳而生 | 11朵向日葵抱抱桶 | 整日无货记录与成交冲突 |

## 请求如何走流程

1. 意图路由先区分销量调查、库存查询、活动查询；混合意图先澄清。
2. 商品解析先识别精确 SKU 或四字花名，再检查朵数、品种、类型是否一致；没有精确身份时使用别名和属性过滤。
3. 通用营销词不作为唯一商品别名。“红玫瑰”可能对应多款；“生日礼物”不能直接选任意商品。
4. 身份有冲突就停在澄清阶段，例如“炽热爱意19朵红玫瑰花束”。不能忽略朵数，也不能用界面选择强行覆盖矛盾。
5. 日期仍需明确。“炽热爱意销量下降原因”只确定了商品，先问分析日期；不会擅自取有数据的日期。
6. 商品、日期、意图确定且数据覆盖后，才进入工具查询、证据分析、报告和人工核验流程。

标题中抱抱桶后面出现“生日花束”，属于营销用途词。解析先排除这些固定短语，再判断成品类型，避免误判。

## 数据口径：成品与花材不能混算

销售件数按一束花束或一个抱抱桶计。卖出 50 件 99 朵花束，就是 50 束，不是 50 朵；成品库存也不能解释为单枝花材库存。

模拟单价分别为 399、129、169、269、199 元，仅为教学设定，不代表市场价。销售金额随模拟成品单价重新计算。部分销售数量保留 100→50，便于复用指标计算与回归测试，不能作为真实闪购店铺经营基准。

所有业务数据均为合成数据。当前只有 SKU 日级数据，没有接入真实闪购平台；未模拟配送半径、履约时效、营业时段、鲜花损耗或原材料配方。康乃馨标题中的“母亲节”不代表十月发生母亲节活动，活动数据明确命名为“模拟闪购鲜花满减券”。

`business_context` 随数据快照传递到报告和界面，用于标明成品单位。它不改变原有证据核验规则，也不自动证明因果关系。

## 运行与学习顺序

```powershell
python -m ecommerce_agent ask "炽热爱意销量下降原因" --preview
python -m ecommerce_agent ask "红玫瑰花束2026-10-23销量下降原因" --preview
python -m ecommerce_agent ask "【怦然心动】19朵红玫瑰花束送女友生日礼物生日花束情人节鲜花同城配送2026-10-23销量下降原因"
python -m ecommerce_agent demo
python -m ecommerce_agent web
```

先看 `data/products.json` 的商品字段，再看 `task_parser.py` 的 `ProductCatalog.resolve` 与 `_constrain`，然后跟踪 `fixtures.py → data.py → tools.py → runner.py`。最后读 `tests/test_flower_catalog.py`：重点理解缺日期、多候选、规格冲突为什么应停止执行。

V0.7 后默认经营快照改由 `flower_business_data.py` 生成，`fixtures.py` 保留为小型算术测试案例。运行 `python scripts/generate_flower_sample.py` 会覆盖 `data/products.json`、`data/sample.json`，请先保留自己的数据。新版说明见[第九步](第九步-花店口语新品与经营数据.md)。

本地网页默认状态目录是 `web-data/flowers`，报告在 `runs/flowers`。Tunnel 的口令在 `web-data/tunnel/flowers/access-token.txt`，本次网址在同目录 `url.txt`，报告在 `runs/tunnel/flowers`。旧工作区的历史记录保留在原目录，不混入鲜花演示。

当前仍是确定性路由与工作流，未调用真实大模型。场景迁移主要训练的是商品建模、实体消歧、数据口径和可追溯分析，而非单纯替换页面文字。
