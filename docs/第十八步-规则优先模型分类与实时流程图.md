# 规则优先、模型分类与实时流程图

本轮将意图路由分成规则、模型分类、用户确认三层。分类模型和后续调查模型是不同阶段，不要把“规则命中、分类模型0次”说成整轮调查一定不调用模型。

## 输入与输出

输入仍是原问题、当前门店、可选商品/日期/事项。输出先是任务卡：路由来源、候选、状态、分类调用数、token用量和耗时。商品、日期与数据通过校验后才排队执行，最终输出网页结果与报告、证据和执行事件。

1. 写动作、明确不支持的时间范围先拒绝，不交模型兜底。
2. 规则命中一个明确意图：直接选路，分类模型0次。
3. 规则命中多个独立事项：直接请用户选择，不让模型替用户决定优先级，也不执行全部分支。
4. 规则没有命中：启用且配置DeepSeek时，最多调用一次分类，8秒超时、256输出token上限，仅发送原问题及四个意图类别，不发送账本。
5. 单一且明确的分类建议：继续本地商品、日期、数据校验。分类器不能补造SKU或日期。
6. 多候选、低/中把握、超时、错误或不合规结构：转用户确认。没有模型配置时也直接提供事项选项。
7. 用户确认后建立关联任务，从原候选中选择，不重复请求模型分类。商品歧义和疑似错字仍独立确认。

`confidence=high/medium/low` 是模型自报把握程度，只用于保守分流，不是经校准的准确率。真实分类准确率仍需要问句评测集验证。

## 去哪里学

- `routing.py / route_question`：规则优先、候选白名单、模型建议验收和安全回退。
- `local_model.py / classify`：一次受限分类协议，没有经营工具执行能力。
- `task_parser.py / parse_task`：路由之后继续检查商品、日期、缺数据。
- `web_service.py / create`：注入分类器、复用父任务候选、幂等命中提前返回，避免顺序重复提交再次分类。
- `web_assets/app.js`：显示路由阶段、分类次数和用户确认选项。
- `flow_view.py`：流程拓扑、输入输出说明、读取源码清单及版本检测。

## 动态流程图

启动 `python -m ecommerce_agent web` 后访问 `http://127.0.0.1:8080/flow`，或点工作台左侧“项目流程图”。页面每5秒检查一次：

- 路由类别直接读取 `routing.py` 的 `ROUTES`。
- 工具清单直接读取 `tools.py` 的表映射与schema定义。
- 受跟踪Python文件变化后提示“运行服务需重启”，不把尚未加载的代码说成已经生效。
- 流程拓扑不会自动理解任意Python重构。改变执行顺序时同步修改 `flow_view.py`，已写入本项目 `AGENTS.md` 的后续协作约定。
- 只解析源码常量，不执行编辑中的文件，不扫描.env或其他凭据。

## 验证结果

135项自动化测试通过，覆盖规则零分类、多意图确认、一次模型分类、不合规输出、超时、候选越界、缺少商品/日期、顺序幂等复用和流程清单自动更新。JavaScript语法和SVG结构检查通过，流程页面已在Edge实际查看。

真实本地HTTP验收：

| 问题 | 路由 | 分类模型 | 经营工具 |
|---|---|---:|---:|
| 99红玫2026-10-25销量怎么样 | 规则，查询完成 | 0次 | 1次 |
| 99红玫2026-10-25销量下降，顺便查库存 | 需要用户确认 | 0次 | 0次 |
| 99红玫2026-10-25出了几束 | DeepSeek分类，查询完成 | 1次，670 tokens | 1次 |
